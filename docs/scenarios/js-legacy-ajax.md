# Scenario 41 — The old AJAX crawling scheme: a site still answering a retired contract

## The question

> This application has `#!` in every URL and something called a fragment meta tag. Is that still
> doing anything?

For search engines, no — Google retired the scheme years ago and renders instead. For this
crawler, yes: honouring the site's own opt-in recovers real content without launching a browser
at all, which on a legacy single-page application is the whole audit for the price of one extra
request per page.

## Covers

- **JavaScript** — Uses Old AJAX Crawling Scheme URLs · Uses Old AJAX Crawling Scheme Meta Fragment Tag

## The chain

**1. Confirm the raw response is empty before deciding anything.**

```bash
seohead render-check --url https://example.com/page
```

An empty single-page-application mount container is detected from the raw HTML by id — `root`,
`app`, `__next`, `__nuxt`, `q-app`, `main-app` — and reported as `empty_shell` without a browser
being involved in that particular judgement. An empty shell plus `#!` URLs is the signature this
scenario is named after.

**2. Crawl in the mode the site itself declared.** In the crawler config:

```json
{"rendering": {"mode": "legacy_fragment"}}
```

```bash
seohead crawl-site --url https://example.com --config ./crawl.json --out-dir ./run
```

Two opt-ins are honoured, and only these two. A URL whose fragment starts with `!` yields the
companion address with `_escaped_fragment_` set to the rest; a page carrying
`<meta name="fragment" content="!">` yields the same address with an empty value. Any other query
parameters on the URL are preserved. A page declaring neither is left alone — the crawler never
invents an `_escaped_fragment_` URL a site did not offer.

**3. Read which pages were fetched that way.** Every page record carries `representation`, and
this mode sets it to `legacy_fragment`. `audit.json`'s `render_escalation` block records the
mode, the URL patterns sampled, the patterns escalated, and how many probe and fetch requests
that cost.

**4. Compare it against the plain static crawl, if the site is worth the second run.**

```bash
seohead compare-crawls --before ./old-audit.json --after ./new-audit.json
```

**5. Verify the run.**

```bash
seohead log-scan --run ./run
```

One of its rules exists for this exact situation: pages measured two ways where only some say
which. A crawl that escalated part of a site and lost the label is a crawl whose averages mean
nothing.

## What comes out

The escalation summary, which is the honest answer to "is this site still on the old scheme":

```json
{
  "render_escalation": {
    "mode": "legacy_fragment",
    "patterns_sampled": 6,
    "patterns_escalated": ["/product/*"],
    "probe_requests": 12,
    "render_requests": 30
  }
}
```

A non-empty `patterns_escalated` in this mode means the site published the opt-in and served the
snapshot. That is a fact about the site, and it is what a migration task should be written from.

## What it costs

One extra plain HTTP request per probed URL and per escalated URL — no browser, no Playwright, no
seconds-per-page. This is by a wide margin the cheapest way to read a legacy single-page
application, which is why the mode exists at all.

## What it cannot answer

- **Whether the snapshot matches what a browser renders today.** The `_escaped_fragment_`
  endpoint is often generated by a pre-render job nobody has maintained since the scheme was
  retired. Stale snapshots are the normal failure here, and comparing one against
  `render-check`'s rendered DOM is the only way to see it.
- **It is not reported as a finding.** The opt-in is read to decide how to fetch, and the mode is
  recorded — but there is no check id that says "this site uses a retired crawling scheme". The
  evidence is in `representation` and `render_escalation`, and somebody has to read it.
- **What Google does with these URLs now.** The scheme is retired; Google renders. The scheme's
  presence is a migration signal, not a ranking one.
- **Anything about a page that declares neither opt-in.** Those were fetched statically and say
  so.
